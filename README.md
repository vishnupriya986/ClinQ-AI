# ClinQ AI

ClinQ AI is a full-stack healthcare-assistance application with account registration/login, private prediction history, research-only heart and diabetes models, one persistent AI conversation per prediction, and secure report/image analysis.

## Features in Phase 1

- React, TypeScript, Vite, React Router, and Lucide React
- Express REST API with PostgreSQL (`pg`)
- Registration with server-side validation and bcrypt password hashing
- Login/logout using an HTTP-only JWT cookie
- Authenticated `/api/auth/me`, dashboard, assessment, history, file, and chat APIs
- PostgreSQL UUIDs, foreign keys, JSONB prediction inputs, and indexes for planned features
- The requested 17 disease-specific clinical intake fields for heart, lung, and diabetes
- Automatic BMI and lung pack-year calculations
- User-owned intake persistence with history and detail views
- A separate persisted chat for each older dataset-model prediction, with history and continue-chat links
- Historical, explicitly research-only UCI heart and diabetes model experiments
- Authenticated PDF text extraction and JPG/PNG vision analysis via a backend-only OpenAI-compatible provider
- Experimental scores are generated by classifiers trained on supplied synthetic datasets and are not real-world or clinically validated disease-risk estimates

## Architecture

```text
client/  React UI, route protection, and API client
server/  Express API, auth, validation, and PostgreSQL access
         server/database/schema.sql defines the relational schema
```

Passwords are hashed with bcrypt. JWTs and database credentials remain on the server. Browser authentication uses a `SameSite=Lax`, HTTP-only cookie; client JavaScript cannot read the token.

## Requirements

- Node.js 22 LTS or newer (includes npm)
- PostgreSQL 16 or newer, either installed locally or run using Docker Desktop
- Python 3.13 (or a supported Python version accepted by the packages in `ml/requirements.txt`)
- An OpenAI-compatible API key and a model that supports image inputs to enable AI chat and image analysis

## PostgreSQL setup on Windows

### Option A: Install PostgreSQL

Download the Windows installer from [postgresql.org/download/windows](https://www.postgresql.org/download/windows/). The EDB installer includes PostgreSQL Server and pgAdmin. During setup, keep port `5432` and remember the password you set for the `postgres` administrative account.

In pgAdmin, connect to the local server and create:

1. A login role named `clinq_app` with a strong password.
2. A database named `clinq_ai`, owned by `clinq_app`.

Alternatively, in SQL Shell (psql), connect as `postgres` and run (replace the example password):

```sql
CREATE ROLE clinq_app WITH LOGIN PASSWORD 'use-a-strong-local-password';
CREATE DATABASE clinq_ai OWNER clinq_app;
```

### Option B: Run PostgreSQL with Docker

From the project root in PowerShell:

```powershell
docker run --name clinq-postgres --restart unless-stopped `
  -e POSTGRES_USER=clinq_app `
  -e POSTGRES_PASSWORD=use-a-strong-local-password `
  -e POSTGRES_DB=clinq_ai `
  -p 5432:5432 `
  -v clinq-postgres-data:/var/lib/postgresql/data `
  -d postgres:16
```

This stores database data in the named Docker volume `clinq-postgres-data`. Docker Desktop must be running before starting the container.

## Environment variables

Copy `.env.example` to `.env` in the project root, then set:

```dotenv
DATABASE_URL=postgresql://clinq_app:your_password@localhost:5432/clinq_ai
JWT_SECRET=a-long-random-secret-of-at-least-32-characters
PORT=3001
CLIENT_URL=http://localhost:5173
NODE_ENV=development
ML_SERVICE_URL=http://127.0.0.1:8000
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=your-server-only-provider-key
OPENAI_MODEL=gpt-4o-mini
```

Use URL-encoded characters if the database password contains reserved URL characters. Generate a JWT secret locally, for example with PowerShell:

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Never commit `.env` or use these development settings in production.

## Installation and database initialization

Install Node.js LTS from [nodejs.org](https://nodejs.org/) if it is not already installed. Open a new PowerShell window and check `node --version` and `npm --version`.

From the project root:

```powershell
npm install
Copy-Item .env.example .env
# Edit .env with your local PostgreSQL credentials and a private JWT secret.
npm run db:setup
```

The database setup command creates the tables, foreign keys, and indexes. It is safe to run again; it does not delete existing data.

Install Python model dependencies and train the historical UCI experiments and the separate synthetic-data models:

```powershell
python -m pip install -r ml/requirements.txt
npm run ml:train
npm run ml:train-synthetic
```

Training writes held-out evaluation JSON and local `ml/artifacts/*.joblib` models. Use the same Python environment to train and serve the artifacts. The synthetic classifier scores estimate only labels in the generated CSVs and are not clinical risk percentages.

## Run the application

Start the local research-model service in one PowerShell window:

```powershell
npm run ml:serve
```

Then run the API and frontend in a second window:

```powershell
npm run dev
```

Open <http://localhost:5173>. The API listens on <http://localhost:3001>. The Vite development server proxies `/api` requests to Express.

AI chat and document analysis require `OPENAI_API_KEY`, `OPENAI_BASE_URL`, and `OPENAI_MODEL` in the root `.env`. OpenRouter is compatible with these settings; for example, use `OPENAI_BASE_URL=https://openrouter.ai/api/v1` and `OPENAI_MODEL=openrouter/free`, with your OpenRouter API key as `OPENAI_API_KEY`. Restart the backend after changing `.env`. The key stays on the backend. If a routed model is unavailable or returns no text, the API reports that instead of fabricating a response. Do not use a provider/model without image-input support for X-rays or other image reports; `openrouter/free` can route to different models, so vision support is not guaranteed.

Run only one service:

```powershell
npm run dev --workspace server
npm run dev --workspace client
```

Build the frontend or start the production API:

```powershell
npm run build
npm start
```

## Authentication API

All request/response bodies use JSON. Auth cookies are sent by the browser; do not move the JWT into frontend storage.

| Method | Path | Access | Purpose |
|---|---|---|---|
| `POST` | `/api/auth/register` | Public | Create an account; returns `201` |
| `POST` | `/api/auth/login` | Public | Verify credentials and set HTTP-only cookie |
| `POST` | `/api/auth/logout` | Public | Clear the auth cookie |
| `GET` | `/api/auth/me` | Authenticated | Return the current user's profile |
| `GET` | `/api/dashboard` | Authenticated | Return database counts scoped to the current user |
| `GET` | `/api/health` | Public | API/database health check |
| `POST` | `/api/intakes/heart` | Authenticated | Score 17 heart inputs with the experimental synthetic model, save score and separate chat |
| `POST` | `/api/intakes/diabetes` | Authenticated | Score 17 diabetes inputs with the experimental synthetic model, save score and separate chat |
| `POST` | `/api/intakes/lung` | Authenticated | Score 17 lung inputs with the experimental synthetic model, save score and separate chat |
| `GET` | `/api/intakes` | Authenticated | List the current user's intakes with their unique chat IDs and file counts |
| `GET` | `/api/intakes/:id` | Authenticated | Read an owned intake and its uploaded files |
| `POST` | `/api/predict/:disease` | Authenticated | Returns `503`; current intake fields do not match existing model inputs |
| `GET` | `/api/predictions` | Authenticated | User-scoped history, newest first |
| `GET` | `/api/predictions/:id` | Authenticated | User-owned prediction details and reports |
| `GET` | `/api/chat/sessions/:id` | Authenticated | Restore an owned prediction- or intake-specific chat, its messages, and files |
| `POST` | `/api/chat/sessions/:id/messages` | Authenticated | Ask about that assessment/report; persist the user's message even if AI is unavailable |
| `POST` | `/api/chat/sessions/:id/files` | Authenticated | Save and analyze a PDF, JPG, JPEG, or PNG up to 10 MB; keep uploads if AI is unavailable |
| `GET` | `/api/files/:id` | Authenticated | Download an owned file |
| `DELETE` | `/api/files/:id` | Authenticated | Delete an owned file |

### Model inputs and datasets

- Current heart, lung, and diabetes forms contain the requested 17 clinical input fields. BMI is calculated from height and weight. Lung pack-years are `(cigarettes per day × years smoked) / 20`.
- The three supplied synthetic CSVs each contain 2,000 rows. Lung workplace exposure is missing on 1,331 rows; gestational-diabetes history and PCOS are missing on 1,065 and 1,056 diabetes rows. Numeric missing values use training-fold median imputation; missing categories are represented explicitly; identical feature rows are held in one grouped fold.
- Synthetic models use a feature-name/order-checked logistic-regression pipeline with grouped out-of-fold Platt calibration. Their held-out evaluation describes performance only on generated data, not real-world patients.
- Each new intake stores its synthetic-label percentage, app-defined score band, and model version in `clinical_intakes`, and creates its own private chat. The UI opens that chat after submission.
- App-defined score bands: Low `<30%`, Medium `30%–<60%`, High `≥60%`. These cutoffs are display bands, not validated clinical risk thresholds.
- Synthetic model output estimates only a label in the supplied generated dataset. It is not a real-world disease probability, clinically validated prediction, diagnosis, or basis for treatment decisions.
- Older stored predictions came from the earlier UCI models, which used different feature sets. Their submitted inputs, research results, model versions, and associated chats are retained unchanged.
- Risk endpoints reject submissions rather than silently ignoring fields or returning outputs from incompatible models.
- The 520 diabetes survey rows include repeated identical feature profiles. Training keeps profiles together in grouped cross-validation/calibration/test partitions to avoid exact-profile leakage.
- Pipeline preprocessing is fitted only within training folds. Logistic regression and class-weighted random forest are compared with grouped stratified CV. Model selection prioritizes recall among near-best ROC-AUC candidates, with a specificity guard. A sigmoid calibration split is separate from the holdout test split. Reports include accuracy, precision, recall/sensitivity, specificity, F1, ROC-AUC, Brier score, and confusion matrix.
- These small historical/survey datasets are not representative prospective clinical cohorts. Scores are dataset-model outputs, not clinically meaningful individual risk probabilities. There are no validated clinical risk cutoffs, and no clinical validation is claimed.
- Lung cancer is deliberately disabled: the commonly available UCI cancer-subtype sample is explicitly biased and has no no-cancer controls, so it cannot responsibly train a lung-cancer risk model.

## Security

- Passwords are hashed with bcrypt; plaintext passwords are never persisted.
- SQL is parameterized. Data access for the dashboard is scoped by the verified session's user ID.
- Auth uses a signed, HTTP-only, same-site cookie and rate-limited login/registration endpoints.
- Document uploads are capped at 10 MB, checked against extension, MIME and file signatures, stored with generated names outside public/static paths, and downloaded only after owner verification.
- Chat/report content is sent only to the configured AI provider, only with the selected document and relevant assessment/session context. Document-analysis consent is required by both the upload UI and API.
- Express sets security headers, only accepts the configured client origin, and returns generic internal errors without stack traces.
- The schema uses UUID primary keys and user-owned foreign keys for predictions, conversations, and files.

## Deployment

Deploy the API and frontend over HTTPS, use a managed PostgreSQL database, set all environment variables in the hosting provider's secret manager, and set `CLIENT_URL` to the exact frontend origin. Set `NODE_ENV=production`; the auth cookie will then use the `Secure` flag. Restrict database network access to the API service and use a dedicated database role. Run `npm run db:setup` as a deployment migration step before starting the API.

## Feature availability and limitations

New intakes now use separately trained models for the three supplied synthetic datasets. Their displayed percentages and Low/Medium/High score bands describe synthetic-label model outputs only, not patient-specific medical risks; the synthetic data has no real-world or clinical validation. Retrain with `npm run ml:train-synthetic` and restart the ML service after changes. Each intake gets an isolated chat session; reopening or continuing it uses that same session. Chat/report AI requires `OPENAI_API_KEY`, `OPENAI_BASE_URL`, and `OPENAI_MODEL` in the backend `.env`; image analysis requires a vision-capable model. Messages and uploaded files remain saved if the provider is not configured, and the UI reports the analysis error rather than presenting a fabricated response.
